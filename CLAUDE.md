# Showdown Replay Stats

Static web page (GitHub Pages) that reads Pokémon Showdown replays and counts kills/deaths per Pokémon for spreadsheets. Singles and doubles.

## Layout
- `site/` — everything that gets published: `index.html` (the league list), `<league>/index.html` (one page per league), both written by `python -I tools/build_pages.py` from `app/league.html` / `app/landing.html` and `leagues.json` (edit those, never the written pages; `tests/test_tools.py` fails when they're stale); a league page's `<base href="../">` makes everything shared resolve from `site/`, and the page's code reaches the league's own files through `DIR` (app/core.js). `style.css`, `app/*.js` (page logic: plain scripts sharing one scope, loaded in order by `app/league.html`; `core.js` shared helpers and state, one file per tab, `sheets.js`, `main.js` (Main viewer / several games added up, opened by Set stats), `startup.js` last: everything that runs at load), `league.js` (season maths and HP-or-% text; no DOM), `parser.js` (log parsing + kill rules, no DOM, also loadable from Node), `teams.js` (team sheet parsing, sheet-to-game matching, max HP; no DOM), `luck.js` (luck score from the rolls parser.js records, with Showdown move data; no DOM), `illusion.js` (which stays on the field a hidden Zoroark could have been: learnsets, HP / status carry-over; no DOM; `site/data/learnsets.json` from `python -I tools/learnsets.py`).
- `site/releases.json` — What's new for visitors (version, title, notes; newest first): the league list shows it, each league page's footer shows the newest version. `CHANGELOG.md` stays the detailed log; add a release entry when cutting a version.
- `site/<league>/` — one folder per league in `site/leagues.json` (`ppppp`, `scl`): `games/` (`draft.json`, `records.json` and the library below), `mock/` (team sheets), `img/` (banner, trainers). The Super Champions League's draft: `python -I tools/scl_draft.py` (from the league's Google Sheet).
- `site/<league>/games/` — the league's game library: `index.json` (id, league, week, players, winner, date, turns, set: the set label from `--set`, games sharing it are one best of three / series, note: two or three words so Games rows stay one line, note_detail: the longer story, shown on hover; sheets: players with a saved paste `mock/<id>-<player>.txt`, kept as given; fixes: players with hand-made sets `mock/<id>-<player>.fix.txt` (pieced from the game when the paste had another Pokémon; read first, matched per Pokémon); top-level `missing`: games played with no saved replay, {week, players, game (null: not known), winner (null: not known)}, filling their set's slots in Games) and a saved copy of each replay. Add games with `python -I tools/add_game.py <link> --league <id> --week "Week 3"` (the `add-game` skill). `site/watch.html` is the replay player (Showdown's replay-embed.js, in a frame on Main viewer).
- `tests/` — `test_tools.py` (`python -I tests/test_tools.py`) tests `tools/add_game.py`'s pure parts. `index.html` + `tests.js` run the parser against real replays in `tests/fixtures/` (hand-counted expectations) and synthetic logs for rules no real replay covers yet. `snapshot.js` / `snapshot.json`: every saved league game's per-Pokémon numbers, checked by `tests.js` ("unchanged", not "right"); rewritten only on purpose with `.claude/skills/test/write-snapshot.ps1`, diff reviewed.
- `.github/workflows/pages.yml` — deploys `main`'s `site/` (the live site) and the `next` branch's `site/` under `next/` (the preview, marked by `mark_preview.py`: noindex, "Preview" strip), on a push to `main` or (through `preview.yml`) to `next`. The only way in to the preview is the hidden link on Pinecord's banner (the Pineco; `banner.egg` in `site/leagues.json`).
- Branches (since 2026-10-29): `main` is the live site, assumed in use at all times: only data (games, team sheets, draft) and finished releases go there. Features go on a feature branch, merge into `next` when they work alone and have passed a code review (`/code-review` on the branch against `next`, findings fixed on the branch first; user 2026-10-29: 41 commits had gone onto `next` unreviewed); merge `main` into `next` after data lands so the preview has it. Versions (semantic versioning, user 2026-10-29): 1.0 = the regular-season viewer, live since 2026-10-29; data-only changes (games, team sheets, draft) never bump it; a fix to the live site is a patch (1.0.1); new features are a minor version (playoffs = 1.1); 2.0 only for a rework. Release, in order: merge `next` into `main`; in CHANGELOG.md rename `## Unreleased` to `## X.Y (date)` and start a new empty `## Unreleased` above it; add the version's `site/releases.json` entry (newest first, what a visitor would notice, no hidden extras); `python -I tools/build_pages.py`; commit; `git tag -a vX.Y -m "X.Y"` on that commit; run the tests (`tests/test_tools.py` checks the headings match releases.json and every release is tagged); push `main` and the tag (`git push origin main vX.Y`); merge `main` into `next`. A live fix: branch from `main`, merge back as a patch release the same way, then merge `main` into `next`. Rollback: re-run the last good "Deploy site to GitHub Pages" run in Actions.
- `tools/video/` — archived 2026-10-29: the stream-video rebuild tools (league games come with replays now); see its README. The 35 rebuilt games stay in the library.

## Commands
- Serve locally: `python -m http.server 8765 --bind 127.0.0.1` from the repo root, then open `http://127.0.0.1:8765/site/` and `http://127.0.0.1:8765/tests/` (fetching fixtures needs http, not file://).
- Served from 127.0.0.1 / localhost, the site never contacts Showdown (`RS.setLocalOnly`, set in `app/startup.js`): only replays saved in `site/<league>/games/` load (team sheets for them in `site/<league>/mock/<id>-<player>.txt`, listed per game in `index.json` `sheets`), move / Pokédex data come from `site/data/` (regenerate from the pokemon-showdown npm package, see docs/knowledge/showdown-replays.md); `site/data/smogon_hp.json` (HP investment per Pokémon for guessed max HP) comes from `python -I tools/smogon_hp.py`, newest month by default, sprites only from `site/sprites/` (gen5 pixel + ani animated; after adding a game with new Pokémon, run `python -I tools/save_ani_sprites.py`). `?online` turns it off. To drop local mode: remove the `localOnly` block in `fetchChecked` and the `LOCAL` lines in app/, then `site/data/`. The tests page doesn't turn this on.
- Run tests headless (no Node installed on this machine; Edge is):
  `msedge --headless=new --disable-gpu --user-data-dir=%TEMP%\edge-headless-rs --virtual-time-budget=15000 --dump-dom http://127.0.0.1:8765/tests/index.html`
  The page title is `PASS`, `FAIL (n)` or `CRASH`. `msedge` isn't on PATH in PowerShell: use `& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"`.
  Shortcut: the `test` skill (`.claude/skills/test/run-tests.ps1`) starts the server and prints the result with failing tests.
- Hidden Zoroark picks (admin only): try them with the Move buttons on the local site, then `python -I tools/set_illusion.py <game id> <p1|p2> <n,n|none|auto>` writes them to `site/<league>/games/index.json`.
- Video-rebuilt games (`site/ppppp/games/video-*`, archived tools): `python -I tools/video/audit_video_games.py` rewrites `docs/VIDEO_GAMES_AUDIT.md` (0 things to check at 2026-10-29); re-run after fixing one by hand.
- Is Showdown up? `python -I tools/showdown_status.py` (about 6 s, UP / DOWN per service: replays, move / Pokédex data, sprites, replay-player scripts). Run it before anything that fetches from Showdown instead of waiting on timeouts.
- Screenshots of the local site: the `screenshot` skill (`.claude/skills/screenshot/shot.ps1`), then send the PNG to the user. The user often works remotely; show changes this way instead of pushing.
- `tests/corpus/` (gitignored): 30 recent Nat Dex replays for surveys and smoke tests; re-download with `search.json?format=gen9nationaldex`.
- A new real fixture: save `https://replay.pokemonshowdown.com/<id>.json` into `tests/fixtures/`, count kills by hand from the log, then add it to `REAL` in `tests/tests.js`.

## Project docs
- Style guide: `docs/STYLE.md` — read it before any `site/*.html|css` change. Its samples page is `tests/style.html` (screenshot it, dark and light, next to any new control).
- Feature list / roadmap: `docs/FEATURES.md` — keep it current (status, new ideas). Focus format is gen9nationaldex.
- Changelog: `CHANGELOG.md` (under Unreleased; on `next`, the next version's lines; data-only lines on `main` go under Unreleased too and ride along with the next release).
- Knowledge: `docs/knowledge/` — replay format facts and kill-rule decisions, marked tested / researched / guess.
- Review list: `docs/REVIEW_QUEUE.md` — things only the user can check.
- League replays: `docs/LEAGUE_REPLAYS.md` — every link the user gave, its week, and whether it's in `site/<league>/games/` yet.
