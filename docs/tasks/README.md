# Tasks (decided work, one session each)

One file per task we've decided to do, written so a fresh session (or a subagent) can pick it up cold:
`S-<n>-<slug>.md` here, closed ones in [done/](done/README.md). Ideas that aren't tasks yet stay in
[FEATURES.md](../FEATURES.md), checks only the user can do in [REVIEW_QUEUE.md](../REVIEW_QUEUE.md). An item lives
in one list.

**One place for each thing.** The task file is the only place for its status, its question for the user, decisions,
progress and resolution. `python -I tools/tasks.py` copies them into the generated blocks (the index below, the
plan's board, the done list); the pre-commit runs it with `--check` and fails on a missing header or a stale block.

## Start
In a new session: `Start S-<n>`. The session reads the file, runs its "Check first", then works the steps. To stop
with work left, it writes a dated Progress section and gives the user the start line.

## Write
New tasks, this README and done/README.md are written by the `agent-habits:scheduler` agent: one call whose
prompt starts with `Queue:` (what, why, evidence, files, what the user must answer first, tracker links). The session
working a task edits that task's file (headers, Decisions, Progress) and reruns `tools/tasks.py`.

`S-<n>-<slug>.md`, the next free number, never reused:

    # S-<n>: <title>

    **Status:** open | started | blocked (short note)
    **Needs you:** <question for the user>
    **Links:** [PROJ-123](https://jira.example/browse/PROJ-123), [spec](https://docs.example/abc)

    ## Goal
    ## Steps
    ## Done when

Needs you: only while the user is needed, required when blocked. Links: optional (Jira, Rally, GitHub issues,
docs); the index shows them. Optional sections: `## State when written (YYYY-MM-DD)` (the index's Written date),
Check first, Decisions, Progress; Resolution is added at close. Link to evidence instead of copying it.

## Answer
The user answers in chat (`S-12: yes`). The session writes the answer, dated, under the task's Decisions, removes
the `**Needs you:**` line, updates `**Status:**` and reruns `tools/tasks.py`.

## Close
The session that did the work reviews its commits, then hands over one `Close:` call to the scheduler (task id,
outcome done / dropped / split, commits, evidence, review findings). The scheduler adds `## Resolution (YYYY-MM-DD)`,
`git mv`s the file into `done/` and reruns `tools/tasks.py`.
