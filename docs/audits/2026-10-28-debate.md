# Debate: the skeptic's audit, point by point

The skeptic's items are in `2026-10-28-skeptic-audit.md` (S1-S22). The original reviewer answers each one. That
reviewer knows the context: a static GitHub Pages site for one draft league, no build step, no Node on the dev
machine, tests in headless Edge, a user who wants plain readable code and short changes, replays rounded to whole
%, and stream-video games rebuilt by reading the screen.

Verdicts: **agree, fix** / **agree, later** / **disagree, keep as is** / **needs the user's call**.

---

### S1. `parseBattle` is 740 lines with ~45 mutable locals
- **Skeptic:** No object owns any state's lifetime, so nothing clears it. `effectSrc` (first audit #1) is the
  symptom. Group state per Pokémon and move to a handler table.
- **Original:** Part conceded. Every map *is* commented with what it holds (`parser.js:199-230`). The length tracks
  the log format: the loop reads one line at a time, the way Showdown writes them. 229 tests pin the behaviour,
  including hand-counted real replays. But the skeptic is right that `effectSrc` has no clear path (only `set` at
  `:671`), and `statusSrc` / `statusOf` / `sleepOf` sit in the same pattern. A full move to a handler table is a big
  change for a user who wants short ones, in the file most of the numbers come from.
- **Skeptic:** Fine. Then fix `effectSrc` now, and add the per-Pokémon state record the next time a rule needs new
  state. Don't add a 15th map.
- **Verdict:** **agree, fix** the `effectSrc` clearing (first audit #1). **agree, later** the per-Pokémon state
  and handler table, done one piece at a time when rules change.

### S2. `app.js`: 1613 lines, ~20 module-level `let`s, caches cleared by hand
- **Skeptic:** `pickZoroark` nulls four caches by name, and a forgotten one was already a bug.
- **Original:** The bug is real: first review #1 was exactly this. Splitting into five script files doesn't remove
  shared state, though. They'd share an `App` object instead, and without modules the script order becomes one more
  thing to keep right. The file is long, but it's grouped by `// ---------- tab ----------` banners.
- **Skeptic:** Then do the cheap half: one `invalidateLeague()`.
- **Verdict:** **agree, fix** `invalidateLeague()`. **needs the user's call** on splitting `app.js` by tab (plain
  readable code vs file size).

### S3. Startup runs mid-file; `var TOUCH` is a temporal-dead-zone workaround
- **Skeptic:** It works only because every path from `setMode` awaits first.
- **Original:** Conceded. The comment at `app.js:1582` ("var: render() may run before this line") admits it. Moving
  `app.js:858-874` to the end is a cut-and-paste.
- **Skeptic:** Agreed.
- **Verdict:** **agree, fix**.

### S4. Seven "load once" caches, four failure behaviours
- **Original:** Partly conceded. Some differences are on purpose: the Smogon file is optional (`teams.js:209`, "null
  if it doesn't load"), so caching null is fine. `libraryReady` failing means the site has no games, and a reload is
  the honest answer. The real problems are `loadDraft` caching a failure (first audit #11) and `loadMockPool`
  caching the result instead of the promise.
- **Skeptic:** One `once()` helper makes the on-purpose cases explicit (`once(fn, { retry: false })`) instead of
  leaving them to chance.
- **Verdict:** **agree, fix** `loadDraft` and `loadMockPool` (cache the promise, retry on failure). **agree, later**
  the shared `once()` helper.

### S5. `toID` five times; draft aliases twice
- **Original:** Conceded on aliases. That *is* first audit #3: `Bet.records` / `Bet.fantasy` group by Showdown name
  because only `app.js:1463` knows aliases. The `toID` copies are one line each, and each module stays loadable
  alone (`bet.js` has no dependency today). That's deliberate.
- **Skeptic:** The one-liners are fine. The alias rule isn't a one-liner.
- **Verdict:** **agree, fix** `Bet.playerKey(draft, name)` used by `bet.js` and `app.js` (closes first audit #3).
  **disagree, keep as is** the one-line `toID` copies.

### S6. The tooltips hard-code draft costs and scoring
- **Original:** Conceded. `app.js:481` builds the sentence from `Bet.SCORING`, and `app.js:495` types the same
  numbers by hand three lines later. Clear drift risk, small fix.
- **Verdict:** **agree, fix**.

### S7. The audit page copies site logic, has dead code, and can't fail
- **Original:** Conceded on the copy and the dead line (`audit.html:53`). On "can't fail": it was written as a
  report, and some flags are expected (Regenerator, Revival Blessing). A `FAIL` title would always be red.
- **Skeptic:** So make only the three exact invariants decide `PASS` / `FAIL`, and leave the rest as a report.
- **Original:** Agreed. Whether `tests/audit.html` gets committed at all (it's untracked) and run from `add-game`
  is the user's call.
- **Verdict:** **agree, fix** `Illusion.picks()` shared by both, and delete line 53. **needs the user's call** on
  committing the audit and running it from the `add-game` skill.

### S8. Samurott-Hisui in `video-cklxgwzl3hm` is a misread, not Regenerator
- **Original:** Conceded. The log has `|switch|p2a: Mr Goon|Samurott-Hisui|100/100` on turn 10 after it left at
  75/100. Samurott-Hisui's abilities are Torrent / Sharpness, and nothing healed it. The first audit put it under the
  Regenerator heading without checking the ability.
- **Skeptic:** And the switch-in HP check would catch the next one.
- **Verdict:** **agree, fix**: add it to `known_errors` (the data; `add_game.py` keeps that field) and add the
  switch-in HP check to the audit.

### S9. Hard-coded data (`MOCK_SHEETS`, `LEAGUE_TAGS`, Challonge URL, 300 HP)
- **Original:** One league, one season, one Challonge bracket. `LEAGUE_TAGS` has one entry. Moving it into data
  adds a field nobody edits. The 300 HP fallback only applies when no row has a max HP. `MOCK_SHEETS` is different:
  it changes with every sheet the user sends.
- **Skeptic:** Accepted, but the 300 should get a comment.
- **Verdict:** **needs the user's call** on moving `MOCK_SHEETS` into `index.json` (a `sheets` field per game).
  **disagree, keep as is** the tag and URL. **agree, fix** a one-line comment on the 300.

### S10. Swallowed errors that change numbers
- **Original:** Conceded for `app.js:919`. A failed `prepareIllusion` silently drops the admin's Zoroark pick, and
  that changes who gets a KO. `app.js:445` is already reported ("Counted n of m"). A missing mock sheet changes HP
  guesses only, and the `~` mark already says "guess".
- **Verdict:** **agree, fix** `app.js:919` (and `:329`, the same notice). **disagree, keep as is** `:445`, `:1434`,
  `:1484`.

### S11. `run()` has no `try / finally`
- **Original:** I looked for something that throws between `:885` and `:939`. The fetches catch, and `applySheets`
  catches per box. I couldn't find a path that throws today (*guess* that none exists). But first audit #2 needs a
  run counter in the same function anyway.
- **Verdict:** **agree, fix**, together with first audit #2.

### S12. The fetch timeout covers headers only
- **Original:** Every league game loads from `site/games/` on the same server (`parser.js:1145-1147`). Only pasted
  non-league links go to Showdown, and a stalled body after good headers is rare (*guess*).
- **Skeptic:** Agreed, it's low.
- **Verdict:** **disagree, keep as is** (note it in `docs/knowledge/` if it ever shows up).

### S13. None of `app.js` is tested
- **Original:** Conceded in part. `seasonMoves`, `dealtKey`, `playerKey`, `spriteId` and the four HP formatters
  are pure and could move to a no-DOM file like `bet.js`. The rendering itself is checked by screenshots (the
  `screenshot` skill) and the user's review queue, which suits a one-person site.
- **Verdict:** **agree, later**: move the pure helpers to a no-DOM file (with first audit #15, the four formatters)
  and test them.

### S14. Coverage holes (luck on real replays, loaders, Python tools)
- **Original:** `addLuck` runs `scoreGame` and `topContributors` (`luck.js:283`, `:294`), so they're covered, though
  only on synthetic data. A hand-checked luck total for a real replay is a lot of manual work for a number shown as
  five words on a die.
- **Verdict:** **agree, later** for `add_game.replay_id` / `summary` tests. **disagree, keep as is** a real-replay
  luck expectation.

### S15. Players / Pokémon rows and sortable headers are mouse-only
- **Original:** Conceded. Most league members use phones (that's why the tap-tip code exists), but taps work there.
  Keyboard and screen-reader users really can't sort or open a player. `docs/STYLE.md` doesn't cover it either.
- **Verdict:** **agree, fix**: buttons in the header cells and the name cells, and `aria-current`.

### S16. Tab roles without tab behaviour
- **Original:** True, and the cheaper fix (drop the roles, use `aria-current`) changes how the tabs look to no one.
  It does touch the STYLE.md "Main tabs" control, though.
- **Verdict:** **agree, later** (with S15, as one accessibility pass).

### S17. CSV / TSV formula cells
- **Original:** Conceded. Copy for Sheets is the main path, and first audit #5 named only CSV. The 18-character
  nickname limit is from memory (*guess*, not checked today). Either way, `+2 Atk` breaking a cell is enough reason.
- **Verdict:** **agree, fix** in `toDelimited`, for both separators.

### S18. Third-party scripts and frames
- **Original:** `watch.html` has to be same-origin to fetch `games/*.json`, and its whole purpose is to run
  Showdown's player. Pinning a copy would break when Showdown changes its format. `referrerpolicy` and `lazy` on the
  frames are free.
- **Verdict:** **agree, later** `referrerpolicy="no-referrer"` / `loading="lazy"`. **disagree, keep as is** on
  vendoring `replay-embed.js`.

### S19. Non-atomic writes to `index.json`
- **Original:** `index.json` and the replay copies are tracked in git, so a truncated file is one `git checkout`
  away. That's lower than "high". But a half-written replay copy that isn't committed yet is trusted by the next run.
- **Skeptic:** Medium, then. The fix is five lines.
- **Verdict:** **agree, fix** (`tools/common.py`: `write_atomic`, `load_index`, `save_index`).

### S20. `add_game.py` relabel allow-list
- **Original:** Conceded. `add_game.py:113` lists three fields. The next field added (`sheets`, if S9 happens)
  would be dropped.
- **Verdict:** **agree, fix**.

### S21. `add_game.py` falls back to a saved copy on a 404
- **Original:** `HTTPError` is a subclass of `URLError`, so a 404 does hit the fallback (`add_game.py:45`). But the
  fallback only uses copies already in the repo, which were real replays. Low.
- **Verdict:** **agree, later**.

### S22. Smaller tool issues
- **Original:** The Challonge key and bye crash are worth fixing the next time the script runs. The rest are one-off
  scripts the user runs by hand.
- **Verdict:** **agree, later**.
